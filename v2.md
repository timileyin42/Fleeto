# Delivra v2 — Feature Roadmap

All new endpoints must have pytest tests before merging.
Test file: `python-service/tests/`

---

## 🔴 High Impact (build first)

### 1. Paystack Billing
**Goal:** Operators can subscribe to Growth/Business plans. This is the revenue engine.

**Backend:**
- `POST /billing/subscribe` — initiate Paystack payment, return checkout URL
- `POST /billing/webhook` — Paystack webhook to confirm payment and upgrade plan
- `GET /billing/status` — return current plan, renewal date, payment history

**Frontend:**
- Wire up the existing Billing page (`/dashboard/billing`) to call the subscribe endpoint
- Show current plan, renewal date, upgrade/downgrade options
- Redirect to Paystack checkout on click

**Tests:**
- `tests/test_billing.py`
  - `test_initiate_subscription_returns_checkout_url`
  - `test_webhook_upgrades_operator_plan`
  - `test_webhook_rejects_invalid_signature`
  - `test_get_billing_status_returns_plan`

---

### 2. Rider Job Assignment Notification (WhatsApp)
**Goal:** Rider receives a WhatsApp message the moment a job is assigned to them.

**Backend:**
- Extend `job_service.py → assign_rider()` to fire a WhatsApp message to `rider.phone`
- Message includes: customer name, pickup address, dropoff address, job ID
- Same fire-and-forget pattern as customer notification

**Tests:**
- `tests/test_jobs.py`
  - `test_assign_job_triggers_rider_notification` (mock Twilio)
  - `test_assign_job_no_notification_if_rider_has_no_phone`

---

### 3. Dashboard Analytics
**Goal:** Operator home dashboard shows live stats — not an empty page.

**Backend:**
- `GET /analytics/summary` — returns:
  ```json
  {
    "jobs_today": 12,
    "jobs_this_week": 58,
    "completion_rate": 94.2,
    "active_riders": 5,
    "total_riders": 8,
    "top_rider": { "name": "Emeka", "jobs_completed": 14 }
  }
  ```

**Frontend:**
- Replace placeholder cards on `/dashboard` with real data from this endpoint
- Show a simple bar chart for jobs per day (last 7 days)

**Tests:**
- `tests/test_analytics.py`
  - `test_summary_returns_correct_job_counts`
  - `test_summary_completion_rate_excludes_cancelled`
  - `test_summary_top_rider_is_most_deliveries`
  - `test_summary_empty_fleet_returns_zeros`

## 🟡 Medium Impact (build second)

### 4. Job Scheduling
**Goal:** Operators can create jobs for a future pickup time.

**Backend:**
- Add `scheduled_at: Optional[datetime]` to `JobCreate` schema and `Job` model
- Jobs with `scheduled_at` in the future stay in `scheduled` status until that time
- New migration: `add_scheduled_at_to_jobs`

**Tests:**
- `tests/test_jobs.py`
  - `test_create_scheduled_job_has_scheduled_status`
  - `test_scheduled_job_cannot_be_assigned_before_time`

---

### 5. Bulk Job Import (CSV)
**Goal:** Operators upload a CSV and create many jobs at once.

**Backend:**
- `POST /jobs/bulk` — accepts `multipart/form-data` with a CSV file
- CSV columns: `customer_name, customer_phone, pickup_address, dropoff_address, notes`
- Returns list of created job IDs and any row errors

**Tests:**
- `tests/test_jobs.py`
  - `test_bulk_import_creates_all_valid_jobs`
  - `test_bulk_import_returns_errors_for_invalid_rows`
  - `test_bulk_import_rejects_non_csv`

---

### 6. Failed Delivery Re-dispatch
**Goal:** When a job is marked `failed`, operator can reassign it to another rider.

**Backend:**
- Extend `assign_rider()` in `job_service.py` to also allow reassignment from `failed` status
- Reset status to `assigned` on reassign

**Tests:**
- `tests/test_jobs.py`
  - `test_reassign_failed_job_resets_to_assigned`
  - `test_cannot_reassign_delivered_job`

---

### 7. Customer Delivery Rating
**Goal:** After delivery, customer sees a 1–5 star rating on the tracking page.

**Backend:**
- `POST /tracking/{token}/rate` — accepts `{ rating: 1-5, comment: str }`
- Saves to a new `delivery_ratings` table
- Only allowed once, only when `status == delivered`
- New migration: `add_delivery_ratings_table`

**Tests:**
- `tests/test_tracking.py`
  - `test_customer_can_rate_delivered_job`
  - `test_cannot_rate_undelivered_job`
  - `test_cannot_rate_twice`
  - `test_rating_out_of_range_rejected`

## 🟢 Nice to Have (build last)

### 8. Email Notifications
- Send tracking link to customer email (if provided) in addition to WhatsApp
- Use SendGrid or Resend

### 9. Rider Earnings Report
- `GET /riders/{id}/earnings` — jobs completed + configurable per-job rate
- Show earnings summary in rider profile on operator dashboard

### 10. Multi-user Access
- Invite team members (dispatchers) to operator account
- Role: `owner` vs `dispatcher` (dispatcher can create/assign jobs but not manage billing)

## Testing Setup

All tests live in `python-service/tests/`.

```bash
# Run all tests
cd python-service && source myenv/bin/activate
pytest tests/ -v

# Run a specific file
pytest tests/test_billing.py -v

# Run with coverage
pytest tests/ --cov=app --cov-report=term-missing
```

### Test conventions
- Use `pytest-asyncio` with async fixtures
- Use a test SQLite DB (already configured in `conftest.py`)
- Mock Twilio and Paystack with `unittest.mock.patch`
- Each test function name describes the exact behaviour being verified
- No test should depend on state from another test
